ORCA GIS API — COMPLETE TECHNICAL DOCUMENTATION
===================================================

Project: SIH26176 — ORCA
Service: ORCA GIS Service
Port: 3005
Main API:
    GET http://localhost:3005/api/gis

Purpose
-------
This GIS service receives a latitude/longitude and combines local GIS datasets
to produce marine/geographic information used by the ORCA decision-support
system.

The service currently provides:
1. Distance from coastline
2. Water depth
3. Marine protected-area information
4. Distance to India's EEZ boundary
5. Nearest Indian port
6. India maritime/fishing-zone classification
7. Placeholder fields for restricted-zone functionality
8. Coordinate validation

IMPORTANT:
The service is a GIS/data-enrichment service. It does NOT by itself decide
whether a fishing activity is legally permitted or safe. The returned
maritime zone should be used as an input to ORCA's risk/decision logic.

===================================================

Required query parameters:

latitude
    Type: number
    Range: -90 to 90
    Meaning: geographic latitude in decimal degrees

longitude
    Type: number
    Range: -180 to 180
    Meaning: geographic longitude in decimal degrees

Example:
    ?latitude=18.8&longitude=72.5

The server converts both values using Number() and validates:
    - numeric value
    - latitude range
    - longitude range

Invalid input returns HTTP 400.

Examples:

    /api/gis?longitude=72.5

Response:
    {
      "success": false,
      "error": "latitude and longitude are required"
    }

    /api/gis?latitude=999&longitude=72.5

    {
      "success": false,
      "error": "Invalid latitude or longitude"
    }

===================================================
4. FIELD-BY-FIELD DOCUMENTATION
===================================================

4.1 coast_distance_km
---------------------
Type:
    number | null

Meaning:
    Distance from the requested coordinate to the nearest loaded coastline
    feature, in kilometres.

Source:
    Natural Earth coastline shapefile:
    data/coastline/ne_10m_coastline.shp

How calculated:
    1. Load LineString/MultiLineString coastline features.
    2. Convert the requested coordinate into a Turf point.
    3. For every coastline feature, calculate the nearest point on the line
       using Turf nearestPointOnLine().
    4. Read nearest.properties.dist.
    5. Keep the minimum distance.
    6. Round to 2 decimal places.

Important:
    This is a geographic distance to the Natural Earth coastline dataset.
    It is NOT the legal maritime baseline distance.

If no valid coastline distance can be calculated:
    null


4.2 water_depth_m
-----------------
Type:
    number | null

Meaning:
    Estimated water depth at the requested coordinate in metres.

Source:
    GEBCO GeoTIFF:
    data/gebco/gebco_2026_n25.0_s0.0_w65.0_e100.0_geotiff.tif

How calculated:
    1. Read the GeoTIFF bounding box.
    2. Check whether longitude/latitude is inside the raster extent.
    3. Convert longitude/latitude to raster x/y indices.
    4. Read the corresponding raster elevation value.
    5. GEBCO interpretation:
         negative = underwater
         positive = land
    6. If elevation >= 0:
         return 0
       Otherwise:
         return absolute value of elevation.
    7. Round water depth to 2 decimal places.

Therefore:
    Land -> 0 m
    Sea -> positive depth in metres

If coordinate is outside the GeoTIFF:
    null

Important:
    The value is based on the raster cell containing the coordinate and is
    not a nautical-chart sounding.

It means:

4.4 inside_restricted_zone

4.5 inside_marine_protected_area
--------------------------------
Type:
    boolean

Meaning:
    Whether the coordinate lies inside at least one loaded marine/coastal
    protected area.

Source:
    WDPA data:
    data/protected_areas/part0/
    data/protected_areas/part1/
    data/protected_areas/part2/

How data is loaded:
    - Search each part directory for a file ending in "-polygons.shp".
    - Read Polygon and MultiPolygon geometries.
    - Keep only areas classified as marine/coastal.

Marine/coastal filtering:
    The dataset does not contain a MARINE field.
    The code checks:
       REP_M_AREA > 0
       OR GIS_M_AREA > 0
       OR REALM contains "marine"

How inside is calculated:
    1. Create Turf point [longitude, latitude].
    2. For every protected-area Polygon/MultiPolygon:
         booleanPointInPolygon(point, polygon)
    3. If any area contains the point:
         inside_marine_protected_area = true

Overlapping protected areas:
    The code does NOT stop at the first match. This allows overlapping
    protected areas to be considered.


4.6 nearest_marine_protected_area_km
------------------------------------
Type:
    number | null

Meaning:
    Distance in kilometres from the requested coordinate to the boundary of
    the nearest loaded marine/coastal protected area.

How calculated:
    1. For each protected area that does not contain the point:
       convert Polygon/MultiPolygon to a line using polygonToLine().
    2. Use Turf nearestPointOnLine().
    3. Read nearest.properties.dist in kilometres.
    4. Keep the smallest distance.
    5. Round to 2 decimal places.

If the point is inside a protected area:
    nearest distance becomes 0.

If no usable protected-area boundary exists:
    null.


4.7 nearest_marine_protected_area
---------------------------------
Type:
    object | null

Returned object:

    {
      "name": "...",
      "wdpa_id": "...",
      "designation": "...",
      "site_type": "...",
      "iucn_category": "..."
    }

Fields come from WDPA properties:

name:
    NAME_ENG, otherwise NAME

wdpa_id:
    SITE_ID, otherwise SITE_PID

designation:
    DESIG_ENG, otherwise DESIG

site_type:
    SITE_TYPE

iucn_category:
    IUCN_CAT

Important:
    The returned area is the nearest area according to the boundary-distance
    calculation, except when the point is inside an area, where that area is
    selected and distance is 0.


4.8 nearest_maritime_boundary_km
--------------------------------
Type:
    number | null

CURRENT MEANING:
    Distance from the requested coordinate to the nearest boundary of the
    INDIA EEZ shapefile.

Source:
    data/maritime/india/india_eez.shp

How calculated:
    1. Load all Polygon/MultiPolygon features from india_eez.shp.
    2. Convert each polygon to a boundary line using polygonToLine().
    3. Create Turf point [longitude, latitude].
    4. For every EEZ boundary:
         nearestPointOnLine(..., units="kilometers")
    5. Keep the smallest distance.
    6. Round to 2 decimals.

IMPORTANT NAMING NOTE:
    The current response key is:
        nearest_maritime_boundary_km

    But the implementation actually measures:
        nearest India EEZ boundary

    It does NOT currently calculate the nearest maritime boundary of every
    country or every maritime zone.

Recommended future rename:
    nearest_india_eez_boundary_km


4.9 nearest_port_km
-------------------
Type:
    number | null

Meaning:
    Straight-line great-circle distance from the requested coordinate to the
    nearest port in the local Indian port dataset.

Source:
    data/ports/indian_ports.json

How calculated:
    1. Load the JSON array.
    2. Keep entries with numeric latitude/longitude.
    3. For every port, calculate Haversine distance.
    4. Keep the smallest distance.
    5. Round to 2 decimal places.

Haversine:
    Earth radius R = 6371 km.

The calculation uses:
    latitude
    longitude
    spherical distance

This is NOT road distance or sailing-route distance.


4.10 nearest_port
-----------------
Type:
    object | null

Returned fields:

    port_id
    name
    state
    port_type
    latitude
    longitude

The selected port is the port with the minimum Haversine distance.

If no valid ports exist:
    nearest_port = null
    nearest_port_km = null


4.11 fishing_zone
-----------------
Type:

Purpose:

Datasets:

===================================================
5. HOW FISHING-ZONE GEOMETRY IS CHECKED
===================================================

The code does NOT calculate:
    distance from coastline <= 12 NM
    distance from coastline <= 24 NM
    distance from coastline <= 200 NM

Instead it uses the actual supplied maritime polygons.

Algorithm:

    input latitude/longitude
             |
             v
    Turf point([longitude, latitude])
             |
             v
    Bounding-box pre-check
             |
             v
    Turf booleanPointInPolygon()
             |
       +-----+-----+
       |           |
     match       no match
       |           |
       v           v
    return       next polygon
       |
       v
    next zone if no polygon matched

Bounding boxes are calculated once when shapefiles are loaded. This avoids
running Turf's polygon calculation for polygons whose bounding boxes clearly
do not contain the point.


===================================================
6. MARITIME SHAPEFILE LOADING
===================================================

Each maritime shapefile is opened using the Node "shapefile" package.

Only:
    Polygon
    MultiPolygon

geometries are accepted.

For each feature:
    - geometry is checked
    - bounding box is calculated
    - feature + bounding box are cached

The service uses an in-memory cache.

After successful loading:
    loaded = true

If another request arrives while data is loading:
    it waits for the existing loading promise.

The current corrected implementation also resets the loading promise if
loading fails, allowing a later request to retry.


===================================================
7. ZONE ID
===================================================

The code tries these property fields in order:

    MRGID
    MRGID_EEZ
    MRGID_TER1
    MRGID_TER2
    GEONAME
    SOVEREIGN1
    TERRITORY1
    ID
    OBJECTID

The first non-empty property is returned as zone_id.

This means zone_id depends on the actual attributes present in the shapefile.

===================================================
11. IMPORTANT LIMITATIONS
===================================================

1. INDIA-ONLY MARITIME CLASSIFICATION
-------------------------------------
The fishing-zone module uses:
    India 12 NM
    India 24 NM
    India EEZ

If a coordinate is in Sri Lankan, Pakistani, Bangladeshi, Myanmar, or another
country's waters, the current service can only say:

    Outside India EEZ

It does not identify the foreign country's maritime zone.


2. LAND IS CURRENTLY REPORTED AS OUTSIDE INDIA EEZ
--------------------------------------------------
A land coordinate is not inside the maritime polygons, so fishing_zone can
return:

    "Outside India EEZ"

The current API does not separately return:
    "Land"

Use:
    water_depth_m == 0

as an additional indication that the point is treated as land by the GEBCO
raster.

Recommended future improvement:
    Add an explicit:
        location_type: "land" | "water"


3. COAST DISTANCE IS NOT LEGAL BASELINE DISTANCE
------------------------------------------------
coast_distance_km is calculated from the Natural Earth coastline.

It should not be used as the legal measurement for:
    12 NM
    24 NM
    200 NM

The maritime-zone shapefiles are used for that classification.


4. nearest_maritime_boundary_km NAME IS BROAD
----------------------------------------------
Current implementation specifically measures distance to India's EEZ boundary.

Recommended name:
    nearest_india_eez_boundary_km


5. GEBCO DEPTH
--------------
Depth is raster-derived.

Land cells are returned as:
    0

The value should not be interpreted as a live bathymetric observation.


6. PROTECTED AREA DATA IS LOCAL
-------------------------------
Protected-area results depend on the WDPA shapefiles currently installed in:
    data/protected_areas/

===================================================
13. ERROR HANDLING
===================================================

HTTP 400:
    Invalid/missing coordinates.

HTTP 500:
    Internal GIS/data error.

Typical causes:
    - missing shapefile
    - missing GEBCO GeoTIFF
    - invalid JSON port dataset
    - malformed GIS geometry
    - runtime dependency problem

404:
    Unknown route.

The GIS server logs errors to the terminal.

The documentation is based directly on the current gisServer.js, gisService.js, fishingZone.js, marineGis.js, and maritimeBoundary.js implementations. For example, the server exposes /api/gis, validates latitude/longitude, and combines getGISData() with getFishingZone().
